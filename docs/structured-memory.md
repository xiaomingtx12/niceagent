# 结构化长期记忆

> 本文记录旧方案。当前运行时和工作台已切换为 [文件式长期记忆](file-memory.md)，不再开放条目状态和版本管理接口。

应用启用 `long_term_memory.enable` 后，根 Agent 获得 `search_memory` 和 `update_memory`。
用户可以在工作区文件的「长期记忆」中管理条目，也可以从对话下方的更新提示查看或撤销。

## 上下文窗口查看

工作台顶部「上下文」展示主 Agent 最近 30 次已接收模型调用的窗口占用和组成。
每次请求在平台模型中间件链最内层采集，包含已装配的系统/技能、记忆、对话及工具定义。
开始调用时展示估算；供应商返回输入用量后补充实际值。统计是单次模型请求，不是整轮累计 token。
模型配置中的 `context_window` 作为完整输入+输出容量；仅有 profile 输入上限时单独标注，不再扣除输出预留。
容量或输出配置缺失时显示未知，图片等非文本块不按 base64 长度冒充 token。

快照通过 LangGraph `CustomTransformer` 接入原生 v3 `custom` 通道，并沿现有工作台事件表/SSE 保存与重放。
公开事件只包含模型名称、类别、计数，不包含系统提示词、用户内容、工具参数或记忆正文。
协议只允许符合 `ContextWindowResp` 的自定义数据，其他框架 custom 事件继续过滤。

## 生命周期

- 用户明确陈述的稳定偏好、事实通过 `user_statement` 保存，依据必须逐字来自本轮用户消息。
- 成功工具结果通过 `verified_result` 提炼为候选，依据必须逐字来自本轮成功工具消息。候选只有经用户确认后才参与加载。
- 修改现有主题使用 `correct`，必须携带 `memory_id` 和 `expected_version`。
- `pause`、`forget` 停止自动加载；历史仍保留以便用户撤销，不是彻底擦除数据。
- 用户可在管理界面重新启用或恢复历史版本。模型不能恢复已暂停或遗忘条目。
- 普通聊天不增加独立的总结模型调用。判断是否值得记忆仍由模型遵循提示词完成，服务端保证依据、状态、版本与容量边界。

## 存储与并发

继续使用已有 LangGraph Store，不新增 ORM 表或迁移。
结构化目录 namespace 为 `("mydify", "agent-memory-entries", account_id, app_id)`，key 为 `catalog`。
与旧文件 namespace 分开，通用文件工具不能修改结构化数据。身份只由服务端提供。

目录最多 100 条（包含候选、暂停、遗忘记录），每条正文最多 1,000 字符，保留最近 20 个版本；目录及历史合计不超过 1 MiB。
PostgreSQL 通过事务级 advisory lock 串行化同一账号、应用的完整读改写，锁等待上限为 5 秒；内存测试模式使用共享进程锁。
当前版本与修订历史在一次 Store 写入内提交。恢复历史会生成新版本；旧版本的撤销请求不能覆盖后续更新。
工具调用回执支持幂等重放，幂等记录随最近 20 个版本保留。

## 注入与兼容

每次模型调用前重新读取目录，按当前用户任务选择相关有效条目，也考虑稳定偏好。
检索使用英文词与中文双字片段；初版不依赖向量数据库，不保证同义改写的语义召回。
正文预算为约 1,800 token，使用偏保守的 UTF-8 字节估算，非供应商实际计费值。整条选择，不截断限定条件。

旧 `/memories/MEMORY.md` 继续在剩余预算内加载；匹配已有条目主题或保留历史内容的行被跳过。
这属于字面匹配兼容，复杂段落和语义冲突仍建议人工整理为条目。其他旧文件继续供 Agent 按需读取。
旧文件保持管理 API 的编辑、下载、删除能力；Agent 的通用记忆文件写入权限关闭，统一使用结构化工具。
关闭开关保留数据并停止访问；删除会话不删除长期记忆。

## 可观测性

`update_memory` 仅在 Store 提交后返回 `memory_update` 成功回执。
前端从原生 v3 工具事件恢复提示，过滤失败、重复保存及其他工具的相似输出。
条目界面展示主题、类别、适用范围、生效状态、来源、更新时间和版本内容。
