# 知识库索引与检索

[返回模块目录](README.md)

## 数据分工

| 存储对象 | 保存内容 |
| --- | --- |
| UploadFile | 上传文件对象的元数据与定位信息 |
| Dataset | 账号归属、Embedding 配置、指纹和维度 |
| Document | 文档处理规则、状态、阶段时间与错误 |
| Segment | 文本片段、节点标识、状态及命中计数 |
| KeywordTable | 全文检索使用的关键词索引数据 |
| Weaviate | 向量及关联元数据 |
| DatasetQuery | 有命中知识库的检索使用记录 |

关系库中的 `Segment.node_id` 与向量节点对应；不能仅凭向量库里有相似文本就认为它有业务访问权限。

## 索引构建流程

文档任务把 ID 列表交给 Celery 的 `build_documents`，Worker 在 Flask 上下文中调用 `IndexingService.build_documents`：

1. 加载 Document 和所属 Dataset，按知识库模型配置初始化 Embedding。
2. 更新解析状态和开始时间，`_parsing` 通过文件提取器取得文本。
3. `_splitting` 使用处理规则切片并准备 Segment。
4. `_indexing` 建立关键词与向量索引所需数据。
5. `_completed` 完成存储与状态更新。
6. 每个文档独立捕获构建失败，记录 ERROR、停止时间和错误信息。

Document 状态与阶段时间是定位进度的依据，不应只根据 Worker 是否打印日志判断完成。启用和禁用文档还需同步向量元数据与关键词索引，不能只修改一列 enabled。

## Agent 检索路径

`create_langchain_tool_from_search` 将已确定的账号、知识库和检索参数封装为工具。模型只提供 query，不负责决定可以访问哪个账号的 Dataset。

`search_in_datasets` 先筛选账号可访问的知识库，检查 Embedding 指纹，再选择检索器：

| 策略 | 实现 |
| --- | --- |
| semantic | 向量相似度检索，带 k 与 score threshold |
| full_text | 关键词全文检索 |
| hybrid | EnsembleRetriever 组合语义与全文，当前权重为 0.5 / 0.5 |

一次检索要求使用相同 Embedding 指纹的知识库。向量维度相同仍不代表坐标空间相同，所以仅检查维度不够。

结果截取至 k，按实际命中的 Dataset 写 DatasetQuery，并批量累加返回片段的 hit_count，最后将片段转为工具文本。当前 DatasetQuery 不是全量查询审计：完全无命中的查询不会因此自动生成每个目标知识库的记录。

## 技术亮点与难点

- 从上传到索引采用异步阶段化处理，HTTP 请求不用等待整份文档向量化。
- Embedding 配置与指纹绑定，阻止不同向量空间直接混合检索。
- 语义和关键词策略共用业务权限与结果记录路径，Agent Core 无需理解数据表。
- 文档启停、片段编辑、知识库删除都跨关系库和向量库，需要保持可检索状态一致。

PostgreSQL、Weaviate 和文件对象存储之间没有同一数据库事务。当前实现通过分阶段更新与错误状态处理故障，不能称为跨存储原子提交或 exactly-once 索引。

也不要把后续可做的 reranker、索引版本切换、全量查询审计描述成现有混合检索默认能力。重试与重建时需核对 node_id、已有片段和失败阶段，不能只重复提交一次任务就假设没有残留。
