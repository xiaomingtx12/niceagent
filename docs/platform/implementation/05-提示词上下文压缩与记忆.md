# 提示词、上下文、压缩与记忆

[返回模块目录](README.md)

## 四种信息不要混用

| 信息 | 保存或使用位置 | 用途 |
| --- | --- | --- |
| 固定规则与应用指令 | 构图时生成 system | 稳定行为、能力使用约束 |
| 本轮输入与规划选项 | 用户消息、工具消息 | 当前目标、补充答案和本轮偏好 |
| 当前上下文摘要 | 框架压缩状态与 checkpoint | 用较少上下文延续当前会话 |
| 长期记忆文件 | 按账号和应用隔离的 LangGraph Store | 跨会话按需读取稳定信息 |

普通总结回答不会自动改变框架上下文；历史摘要也不等于自动写入长期记忆。

## 提示词装配与缓存

`build_app_system_prompt` 按固定顺序先装配平台规则、任务数据与规划规则，再放应用名称、说明和业务指令，最后按已启用能力添加记忆、异步任务、压缩和路径说明。

字符串拼接本身不会破坏供应商提示词缓存。缓存关心最终 token 前缀和供应商策略：每次相同输入得到相同前缀，通常有利于复用；在前部加入时间、随机 ID、不断变化的目录或本轮状态则会改变前缀。

平台将本轮规划选项保存在用户消息中，表单恢复走 resume，不重复添加用户消息。原生 TodoList、Filesystem、Skills 和摘要规则继续由框架提供；平台补充业务约束，不复制一套工具手册。异步工具的原生说明提前纳入 system，并关闭对应实例重复追加。

这只提供缓存稳定性的条件，不保证命中。还需结合实际输入用量、cached token 与 system/tools 指纹判断；指纹是排障辅助，不是供应商的缓存键。

## 规划的行为边界

自动模式由模型根据任务复杂度决定是否使用 `write_todos`；显式模式用提示词要求先建立或调整计划，再执行主要工作。信息不足时先列澄清事项并询问，不编造尚不明确的步骤。

显式模式仍是模型行为约定，不是另一个强制规划循环或计划批准流程。`write_todos` 负责维护计划状态；计划未完成不必然阻止 Agent 自然结束。工具调用过程与计划状态分别展示。

## 窗口预算与百分比

当前模型元数据缺省窗口为 **400,000 token**，来源为 `DEFAULT_CONTEXT_WINDOW`；不是根据之前对话里提到的数字写死在页面。

`with_context_budget` 结合模型输入限制、总窗口与输出预留计算可用输入上限，再扣除安全余量。安全余量按上限约 2% 计算，限制在 256—4096 token；无法得到输入预算时不伪造一个值。

上下文观测在模型调用前生成估算，返回后使用供应商提供的真实输入用量补充。多媒体不能按 base64 字符长度当作真实 token。

页面中两个比例含义不同：

- 窗口占用：当前请求输入加输出预留，与完整窗口比较。
- 压缩进度：压缩器自己的近似输入计数，与压缩触发阈值比较；有预算时当前观测阈值为预算的 85%，缺省观测阈值为 170,000。

不要用整轮累计 token 替代单次请求占用，也不能从窗口圆环推断精确的供应商剩余额度。

## 自动与主动压缩

构图时自动压缩使用 DeepAgents 原生摘要能力；主动 `compact_conversation` 复用同一套预算及原生摘要策略。平台适配媒体卸载、同批重复调用拒绝、失败回执和摘要校验。

主动流程读取有效消息，确定可压缩区间，归档媒体与原文，生成摘要，再构造框架状态更新。工具返回“无需压缩”不表示失败；普通自然语言总结不替代这个过程。

摘要模型返回、框架压缩更新、checkpoint 保存是不同阶段。前端事件区分摘要生成与保存，避免摘要刚生成就声称状态已持久化。原文归档路径也不代表每个媒体都成功保存。

## 长期记忆的实际读写

图使用 `memory=None`，没有启用框架自动文件内容注入。长期记忆通过 `/memories/` 文件路由访问；`AgentMemoryMiddleware` 提供删除工具，不在每轮开始时自动读取偏好全文、列目录或总结写入。

按需定位使用 ls/glob/grep，已知路径直接 read_file；分类为 preferences、background、experience。当前有效上下文足够时可以复用，已知发生变化或需要修改时重读。

写入方面，管理接口使用 `expected_sha256` 检测并发编辑；作用域事务锁保护检查与写入。先检查冲突，再判断正文是否相同；相同路径、相同正文不重复写 Store，不更新时间。Agent 文件工具维持新建和编辑的语义，不能把 write_file 当覆盖接口。

真实提交后通过 `memory_file_update` 通知页面刷新。通知表示文件改变，不表示模型已经使用新内容；文件写入与通知落事件库也不是同一个原子事务。

因此当前属于用户可编辑、按主题组织、按需读取的文件型长期记忆。模型可以记录验证过的经验，但没有独立的效果评估、冲突消解和自动淘汰闭环，不能描述成已经完成“自进化系统”。
