## 文档与代码分别保留什么

- 本目录保留跨文件调用链、关键数据、设计理由、失败边界、技术亮点与限制。阅读者应能据此找到实际实现并解释取舍。
- 源码注释保留局部不变量，例如“必须先检查版本再判断内容相同”“回调异常不能被框架吞掉”。这些约束应与代码放在一起，不能全部移到文档。
- 模块 README 保留就近阅读入口。已有的 [Agent Service](../../../internal/service/agent/README.md)、[Core 执行](../../../internal/core/agent_v2/execution/README.md)、[测评](../../../internal/service/agent_evaluation/README.md) 是具体实现的补充导航。
- [平台总览](../00-平台总览.md) 与原有 01—08 篇保留业务介绍、面试和简历用途；具体运行行为以本目录引用的源码和已确认业务约定为准。

不在文档里逐行翻译代码，也不为每个辅助方法另建一篇。模块边界应围绕可独立理解的业务链路，而不是目录数量。

## 事实与建议的写法

各篇“实现”描述已存在的代码；“边界”明确当前不能保证的事情。没有测量数据的优化只解释机制，不写“提升百分之多少”。需要新增租约、任务队列、索引或事务合并的内容写成待改进事项，不写成系统现状。

数据库业务状态、框架 checkpoint、流式展示状态、供应商计费用量是不同事实来源。排障时先确认正在讨论哪一个，不能用其中一个替代其他几个。

## 维护约定

改变授权范围、状态机、事务顺序、持久化位置、缓存边界或后台执行方式时，同步修改对应专题和代码入口。调整纯局部实现时优先更新源码注释。参数以源码为准；本文记录的阈值用于解释当前实现，不代表跨版本承诺。

本文档核对没有启动服务、调用模型、操作数据库或运行测试。
