# 事件协议与前端流式体验

[返回模块目录](README.md)

## 三层转换

1. Core 消费 LangGraph/DeepAgents 流，识别消息、工具、值更新和框架生命周期。
2. `agent_protocol` 将规范化事件绑定业务身份与编号，投影为公开协议。
3. 前端通过统一适配器接收事件，用消息、执行过程、上下文、任务等视图展示。

公开通道由 `EventChannel` 定义：`messages`、`values`、`tools`、`lifecycle`、`custom`、`input.requested`。消息开始、文本增量、工具参数增量并非同一种载荷，不能只用字符串拼接处理所有事件。

`seq` 表示顺序，事件 ID 用于身份识别，namespace 区分主图与子图。框架根图结束信号不直接等于业务提交成功：数据库结算完成后才能形成可信的业务终态。

## 实时发布和持久化的真实顺序

当前 `AgentExecutionEventBuffer.emit` 在锁内先登记待写队列，再发布到内存实时尾部；独立写线程随后批量落库。它不是“每条事件提交数据库后才发送给浏览器”。

| 机制 | 当前值及目的 |
| --- | --- |
| 待写队列 | 最多 512 条，持续拥塞时对生产者施加背压 |
| 合批提交 | 最多 128 条，未满批时最多等待约 250ms |
| 内存实时尾部 | 保留最近 2048 条，正常订阅不为每条事件查询数据库 |
| 收尾 | 排空并回收写线程；失败批保留，调用线程补写失败则按失败结算 |

亮点是把首字交付与单条数据库提交延迟分开，同时用有界队列限制内存。代价是进程骤停时，已经实时展示但尚未提交的尾部可能丢失；不能承诺所有已显示事件都能永久重放。

## state、snapshot、stream 的分工

| 接口能力 | 内容 | 适用时机 |
| --- | --- | --- |
| state | 最近问答、Run 摘要、公开状态、待填内容 | 进入会话和切换会话 |
| snapshot | 某个 Run 的恢复投影与对应水位 | 查看过程、恢复订阅 |
| stream | 指定 Run 的实时变化和恢复交付 | 正在执行时 |

恢复快照把已经发生的大量增量压成可恢复的执行记录，再用与快照配套的水位衔接后续事件。它减少重复重放，不等于对总响应字节数建立了固定上限；大工具结果或较长完整过程仍可能使快照较大。

服务端在数据库已保存前缀与内存实时尾部之间切换，订阅者落后超出保留范围时回库补齐。扫描游标按已扫描序号前进，过滤不公开事件不应卡住续传。

前端 `workbench-sse-fetch` 将一次订阅绑定到固定 Run；重试仍使用该 Run，并重新申请配套 snapshot。它不把“网络已经收到的字节游标”直接当成“页面已经应用的状态游标”。

## 前端卡顿与切换竞态

一次卡顿可能同时涉及 JSON 解析、SDK 状态归并、Vue 响应式更新、Markdown 解析、DOM 布局和滚动。仅凭接口体积或控制台一条警告不能定位根因。

当前已实现的控制点：

- `use-agent-workbench` 共用 stream handle，通过当前会话身份判断事件归属，快照和实时事件使用浅引用。
- 重连与恢复逻辑集中在 transport/recovery，避免多个视图各自再开一条事件订阅。
- Markdown 使用共享 Web Worker；每个组件只保留一份尚未执行的最新正文，避免流式输入堆积大量过期解析。
- Worker 不可用时保留可读原文，不把重解析转回主线程；最后一个组件卸载后释放 Worker。
- 后台任务详情请求使用 AbortController；切换对象、退出或关闭时取消请求，并核对响应身份，防止迟到结果串到新任务。

Abort 解决资源取消，身份校验解决已经返回的旧响应；两者不能互相替代。Worker 主要移出解析开销，也不意味着大 DOM 的渲染和布局已经没有成本。

## 计划和已确认信息

`write_todos` 工具调用属于执行过程，`todos` 属于当前计划状态，已确认表单答案属于交互历史。它们可以同时展示：正文过程说明“调用发生了什么”，对话框上方的计划说明“当前还有什么工作”。Run 结束不等于所有待办自动完成。
