# 测评、证据与用量分析

[返回模块目录](README.md)

## 两种测评不是同一条评分链

| 模式 | 输入及执行范围 | 结果依据 |
| --- | --- | --- |
| 历史回答评分 | 冻结原任务描述、回答和标准；裁判不执行工具 | 标准覆盖、原文引用、固定分档 |
| 执行验收 | 冻结草稿模型、提示词和要求；独立图生成并修订 | 实际候选、确定性检查、逐项裁判与最终一致性 |

每次重评创建新的 AgentEvaluation，不修改原会话。执行验收使用独立内存 checkpoint 和 StateBackend，不接入生产工具、知识库、Skill、子 Agent、长期记忆或原附件，因此不是完整生产任务回放。

## 提交与后台生命周期

1. Service 校验来源归属和源运行终态，从数据库读取材料，不接受前端提供的假答案。
2. 以账号、应用、request_id 生成幂等身份；已有记录必须核对材料选择、标准、模式和裁判配置。
3. 冻结快照，创建 queued 记录，事务提交后向 Celery 投递记录 ID。
4. Worker 通过 EvaluationTaskStore 条件更新认领 running，重复投递不会再次执行已认领任务。
5. 加载模型后结束读取事务，再执行模型调用；进度及最终结果另开短写事务。
6. 进度和完成写入同时检查运行状态与提交后 15 分钟的截止时间，防止迟到结果覆盖终态。

任务状态 completed 表示报告生成完毕，不代表内容通过验收。Celery 投递失败、超时或执行失败进入 error，并保留已保存的轮次。截止时间检查不是中断阻塞调用的独立定时器；Worker 的软硬超时承担另一层时长限制。

## 历史评分的证据约束

裁判输出由 Pydantic 解析，标准 ID 必须精确覆盖 1 到 N，不能重复、遗漏或添加；引用必须是 query/answer 中的逐字子串，通过项必须有非空引用。

| 结论 | 分数 |
| --- | --- |
| passed | 1.0 |
| failed，部分满足 | 0.5 |
| failed，不满足 | 0.0 |
| insufficient_evidence | null |

存在弃评时，总体 score/pass_rate 留空，同时单独提供可评范围的分数、通过率和覆盖率。这样不会将证据不足算作通过或零分。引用存在只能证明裁判确实引用了材料，不能证明回答中关于真实文件、外部事实的自述已经被验证。

## 执行验收如何防止自述通过

`candidate_snapshot` 从当前图状态提取实际回答和虚拟文本文件，产生 EvaluationCandidate。回答不能回退到上一轮；文件格式异常和超限直接报错。

裁判通过无候选参数的 `inspect_candidate` 读取本轮候选，不能提交另一份更好的答案替换被评材料。程序检查支持 contains、file_exists、json_keys；同一候选最多解析一次 JSON。

EvaluationEvidence 绑定原候选；EvaluationRound 分开记录裁判 verdict 和平台核验后的 status。原生 Rubric 负责评分与修订循环，平台校验 C 标准全覆盖、当前证据已读取、通过结论与客观检查不矛盾。

最终 `_execution_result` 重新提取交付物，只有末轮 satisfied、回答非空、候选及证据哈希匹配最终状态且程序检查通过，才 accepted。图正常结束、裁判说通过或有文件都不足以单独放行。

当前边界：回答 48,000 字符；最多 50 个文件、合计 96,000 字符；独立执行使用 v2 UTF-8 文本文件。file_exists 检查存在且非空白，不运行文件内容，也不核验程序功能。

`max_iterations` 是评分轮数上限，第一次评分计入；当前请求允许 1—5 轮。执行验收另外使用模型调用 30、工具调用 50、图递归步数 150 的保护，三者与评分轮数不是同一指标。

## 用量分析口径

AnalysisService 从 ConversationTurn 读取累计 token、缓存 token、推理 token、调用次数、耗时和价格等数据，按应用归属查询。当前概览比较截至当天零点的最近 7 天与前 7 天，并筛选回答非空的 Turn，使用带日期和应用 ID 的 Redis 缓存。

因此这些指标不是包含所有失败、空回答任务的全量运行成功率，也不是最近 168 小时实时仪表。查看供应商单次缓存命中应看模型调用观测，而不是直接拿整轮 cached token 总数计算一次请求命中率。

## 技术亮点与边界

- 独立冻结材料，使重新评分不污染生产对话。
- 语义裁判与确定性核验分离，程序只承担能实际验证的部分。
- 内部使用候选、证据和轮次对象，仅在工具返回和持久化边界转换为报告字典。
- Store 集中保护状态更新；Schema 只处理 HTTP，评分分档与引用规则位于 Entity。
- 裁判仍可能对语义判断出错，且独立环境不覆盖生产全部能力；报告必须保留范围说明。
