# NiceAgent 项目简历写法

> 以下内容按“总结：具体描述”组织。括号中的 `[N]`、`[X%]` 需要根据真实项目数据替换；没有确认的数据不要直接写进简历。

## 一、项目名称与项目概述

**项目名称：NiceAgent 智能 Agent 应用平台**

**项目概述：** 面向企业用户提供 Agent 应用创建、配置、调试、发布和运行能力，支持模型、知识库、API Tool、MCP、Workflow、Skill、Workspace 和长期记忆组合，并通过工作台、WebApp、开放 API 和内部协议服务不同调用场景。

**技术栈：** Python、Flask、SQLAlchemy、PostgreSQL、Redis、LangChain、LangGraph、DeepAgents、Weaviate、Vue 3、TypeScript、SSE、Docker。

**个人定位：** 负责平台前端、后端和 Agent 核心能力的端到端开发，并经历了以 LangGraph 为核心运行时向 DeepAgents 演进的架构升级。

## 二、推荐放在简历上的项目亮点

- **搭建 Agent 应用全生命周期平台：** 设计并实现应用创建、草稿编辑、调试、发布、取消发布、版本回退和 WebApp 凭证管理流程，将模型、提示词、知识库、工具、工作流和记忆统一抽象为可配置 Agent Definition。

- **端到端负责平台建设：** 从 Vue/TypeScript 前端页面、交互状态和 SSE 消费，到 Flask/Python 后端接口、领域 Service、SQLAlchemy 数据模型和 Agent Runtime，打通应用配置、运行、交付和评测链路。

- **设计可恢复的 Agent 执行模型：** 将一次用户提问拆分为 Conversation、Conversation Turn、Agent Execution 和 Agent Event，支持运行中、等待输入、完成、失败、取消等状态流转，并保留完整执行上下文。

- **实现可靠的流式事件机制：** 基于 SSE 推送模型输出、工具调用、知识库检索和生命周期事件，以单调递增 sequence 持久化事件，支持客户端断线重连、历史回放和重复事件去重。

- **解决长任务的人机协同问题：** 基于 LangGraph interrupt 实现 Agent 运行中主动提问，使用 Input Batch 和 Submission 记录表单状态及答案幂等性，支持用户补充信息后恢复原 Execution。

- **完善并发控制与幂等设计：** 通过 Conversation 行锁、部分唯一索引、输入消息幂等键和进程内执行跟踪，避免同一会话重复创建任务、重复提交表单和并发结算覆盖。

- **建设企业级知识库链路：** 实现文件上传、文档解析、文本切分、Embedding、Weaviate 向量写入和 Agent 检索流程，使用 Dataset、Document、Segment 和 DatasetQuery 管理知识状态、检索审计和命中统计。

- **实现多能力运行时装配：** 设计 AgentFactory，将模型连接、Skill、API Tool、MCP Tool、Workflow、Dataset、Workspace、长期记忆和审核中间件按发布配置动态装配到 LangGraph 执行器。

- **支持多入口统一复用：** 将调试页、WebApp、开放 API、Creator 任务中心和内部 Agent Protocol 统一收敛到 AgentRunService，仅在身份解析、配置来源和返回协议上做入口适配，降低多渠道重复实现成本。

- **主导 Agent 运行时升级：** 将早期以 LangGraph 为核心的执行实现演进为基于 DeepAgents 的 Agent Runtime，在保留会话、事件、取消和恢复协议的基础上，统一接入 Agent 装配、工具调用、Workspace、长期记忆、Skill 和 SubAgent 能力。

- **建立 Agent 测评与质量闭环：** 基于历史 Execution 创建独立 Agent Evaluation，保存任务快照、评测标准、Judge 配置和评测器版本，支持结果追踪、重复测评和应用质量分析。

## 三、后端开发方向写法

- **负责核心领域模型设计：** 梳理 Account、Application Owner、End User、Conversation、Turn、Execution、Agent Definition 等领域概念，建立应用配置、会话运行、资源授权和测评之间的边界。

- **负责 Agent 运行服务开发：** 实现任务启动、后台执行、状态查询、事件订阅、取消、表单提交、运行恢复和孤儿任务收敛等核心服务，统一处理鉴权、幂等、事务和异常。

- **负责 Agent 装配与执行链路：** 基于 LangChain/LangGraph/DeepAgents 实现模型、工具、知识库、Skill、SubAgent、Workspace 和审核能力的动态组装，并将底层事件转换为平台协议事件。

- **负责运行时迁移与兼容：** 抽象 AgentExecutor、AgentEvent 和 AgentRunContext 等平台边界，隔离 LangGraph 与 DeepAgents 的底层差异，迁移期间保持既有 API、数据库状态机、SSE 事件和前端消费方式稳定。

- **负责数据库和事务设计：** 设计 App、AppConfig、AppConfigVersion、Conversation、ConversationTurn、AgentExecution、AgentExecutionEvent、Dataset、Document、Segment 和 AgentEvaluation 等核心表，使用 JSONB 保存可扩展配置，使用唯一索引和状态约束保证一致性。

- **负责异步任务和流式通信：** 将耗时 Agent 执行从 HTTP 请求中解耦，通过后台执行线程和 SSE 事件流提升交互体验，并以数据库事件表作为断线续传和历史回放的数据源。

- **负责前后端闭环交付：** 设计应用配置、工作台、任务中心、知识库、Workspace、测评和 WebApp 等 Vue 页面及 Hook/Store，同时完成对应 API、鉴权、事务、异步执行和错误协议。

- **负责安全与资源授权：** 实现 JWT、API Key、WebApp Token 和内部 HMAC Token 等多种认证方式，校验应用、账号、End User 和资源归属，避免客户端覆盖可信身份和调用入口。

## 四、适合强调技术难点的写法

- **长流程可恢复：** 针对 Agent 执行时间长、可能等待用户输入和网络中断的问题，将执行状态、事件游标、待填表单和运行快照持久化，使任务可以暂停、恢复、取消和断线续传。

- **并发一致性：** 针对同一会话重复点击、网络重试和多请求并发场景，采用会话行锁、数据库部分唯一索引和业务幂等键组合控制，保证一个会话最多只有一个占用中的 Execution。

- **配置与运行解耦：** 将草稿配置、发布配置和运行时配置指纹分离，调试读取草稿，生产入口读取发布快照，运行中的任务冻结启动时配置，避免后台修改影响线上执行。

- **协议统一：** 将 LangGraph 原始事件规范化为平台统一事件模型，再由不同入口投影为工作台、WebApp 和内部协议格式，降低核心执行引擎与外部协议之间的耦合。

- **关系库与向量库协同：** 使用 PostgreSQL 保存 Dataset、Document、Segment 等权限和处理状态，使用 Weaviate 保存向量索引，通过 `segment.node_id` 建立业务片段和向量对象的关联。

## 七、简历中不要直接这样写

- “负责 Agent 平台开发”：范围太大，无法体现个人贡献。
- “使用 LangChain、LangGraph、PostgreSQL”：只有技术名词，没有业务结果和解决的问题。
- “实现聊天、知识库、工具等功能”：像功能清单，缺少架构难点。
- “提升系统性能和稳定性”：没有说明通过什么机制、改善了什么指标。

建议改成“**解决什么问题：采用什么设计：带来什么结果**”。如果没有可公开的线上指标，可以量化代码规模、入口数量、状态类型、资源类型、测试覆盖范围、处理文档量或故障恢复能力，但不要虚构业务数据。
