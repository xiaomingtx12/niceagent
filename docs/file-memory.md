# 文件式长期记忆

核对日期：2026-09-11；以下按 `e0e8544` 之后移除旧记忆兼容代码的工作区实现说明。

编排页只负责 `long_term_memory.enable` 开关。开启后，工作台开放长期记忆文件入口，根 Agent 获得文件记忆能力；关闭后隐藏入口并停止读写，现有数据保留。

## 用户操作

- 用户偏好、背景信息、经验方法分别对应 `/memories/preferences/`、`/memories/background/`、`/memories/experience/`。
- 每个文件一个主题；文件列表显示名称、摘要和更新时间。
- 新建和编辑直接进入文档编辑器，标题即文件名，正文自动保存。
- 修改分类或标题通过一次原子请求移动文件，不先复制再删除。
- 删除直接移除 Store 文件，不提供候选、暂停、版本历史、撤销或回收站。
- 自动保存失败保留草稿，支持重试或明确放弃修改；关闭面板前等待保存完成。

## 框架装配

文件内容保存为 LangGraph Store 记录，DeepAgents `StoreBackend(file_format="v2")` 将其映射为虚拟文件。`AGENT_MEMORY_BACKEND=postgres` 时使用 PostgreSQL 持久化，`memory` 模式使用进程内 `InMemoryStore`，重启会丢失；后者也用于本地隔离验证。

namespace 为 `("mydify", "agent-memory", account_id, app_id)`。WebApp 的 account_id 来自当前登录使用者，创建者入口来自当前创建者；身份由服务端确定。同账号、同应用的不同会话共享记忆，模型名称不参与作用域；同步子 Agent 的默认文件权限不开放父 Agent 的 `/memories/`。

`ReloadingMemoryMiddleware` 继承原生 `MemoryMiddleware`，保留原生学习提示和系统消息注入，每次模型请求刷新记忆目录。`create_deep_agent(memory=None)` 避免重复注册默认中间件。

`/memories/.index.md` 是 Backend 动态生成的只读目录，不占用用户文件，也不出现在工作台。目录部分以 3,500 UTF-8 字节为阈值；单份偏好正文不超过 900 字节、追加后总计不超过 3,600 字节时才自动注入。目录溢出提示占少量额外字节，整体可概括为约 3.6 KB。其他正文通过原生 `read_file` 按需读取，未进入索引的文件可通过 `ls` 查找；工具读取正文仍会额外占用上下文。

Agent 使用原生 `write_file` 和 `edit_file` 新建、纠正记忆；仅删除操作补充 `delete_memory_file`。文件工具成功回执经现有工具事件投影为“记忆已更新”。不增加独立总结模型调用。

## 保存决策与调用时序

用户明确要求记住或纠正稳定信息时，模型根据提示规则查找相关主题，并选择新建或修改文件；已验证的可复用经验也可记录。不确定推测、临时任务状态、一次性要求和凭据被提示为不应保存的内容。提炼、归类和重复主题合并由模型判断，代码没有把这些判断变成确定性内容审核。

一次保存依次经过：模型读取目录和相关文件 → 调用文件工具 → Backend 校验路径、容量及写入条件 → 事务提交 → 返回真实工具结果 → 下一次模型调用刷新目录。记忆文件已写入不代表模型一定正确使用其内容。

当前检索使用目录及 `ls/glob/grep/read_file`，没有记忆 Embedding、向量召回或语义排序，也没有独立的逐轮总结模型调用。用户可在界面查看、编辑、重命名和删除同一份文件数据。

## 一致性

HTTP 写入与 Agent 文件操作共享作用域事务锁。工作台传递当前正文的 SHA-256 摘要，拒绝覆盖其他会话的新修改；空摘要表示仅允许新建。摘要不构成版本历史。PostgreSQL 锁跨进程生效，内存测试使用进程锁。

单文件 64 KiB、作用域最多 100 个文件、总容量 1 MiB。内部索引不可编辑。Agent 写入沿用原生“新建不能覆盖、编辑须精确匹配”的语义。

## 当前实现边界

只保留文件记忆。旧结构化条目实体、仓储、中间件、Schema 和兼容导入模块均已移除；列表读取与动态索引生成只读，不读取旧 catalog，不转换旧数据，不创建导入标记。应用文件清理也只面向当前文件记忆空间。

当前不提供候选审批、暂停、修订历史、撤销或回收站。删除会移除 Store 文件及后续目录中的条目，已经进入会话消息、摘要或 Checkpoint 的原文不会同时被清空。“不要根据历史内容重新创建已删除记忆”由提示规则约束，没有独立删除墓碑机制。

应用关闭记忆后保留已有数据。代码清理没有执行真实数据库删除或迁移，历史结构化数据不再被当前机制自动导入。

## 验证记录

本轮实现调整使用临时脚本验证，没有新增测试文件或操作真实数据库：

- 文件列表和索引生成没有写操作，也不会读取或导入旧结构化目录。
- 文件增删改查、重命名、过期摘要冲突、容量限制、多页读取与账号隔离通过检查。
- 去掉旧记忆实体依赖后，当前文件记忆的上下文估算结果保持一致，Core、记忆 Handler 和 Schema 可正常导入。
- 使用已安装的 DeepAgents、脚本化本地模型、`InMemoryStore` 和内存 Checkpointer，验证跨会话写入和读取、同轮目录刷新、删除后刷新，以及新会话中目录不再出现已删除文件。

上述验证覆盖真实框架链路，不证明线上模型会正确提炼或合并任意记忆；真实供应商模型、PostgreSQL 联调和浏览器交互需分别验证。本次文档更新没有重新执行这些运行检查。
