# ⑩ 测评与质量：和生产经营隔离的评分

[返回组件地图](00-组件地图.md) · 业务链路见 [测评、证据与用量分析](../platform/implementation/10-测评证据与用量分析.md)

## 这块组件在干什么

测评**不是**生产 Run 的一种状态。每次重评新建 `AgentEvaluation`，不改原会话。两种模式共用提交/认领，评分链完全不同。

| 模式 | 吃什么 | 凭什么下结论 |
|---|---|---|
| 历史回答评分 | 冻结的题面、回答、标准；裁判无工具 | 标准覆盖、原文逐字引用、固定分档 |
| 执行验收 | 冻结的草稿模型/提示词/要求；独立图生成修订 | 实际候选 + 程序检查 + 逐项裁判 |

执行验收用独立内存 checkpoint 和 `StateBackend`，**不**接生产工具、知识库、Skill、子 Agent、长期记忆、原附件。所以它不是完整生产回放。

## 当前怎么做

### 提交与认领

1. Service 校验来源归属和源 Run 已终态，材料从数据库读，不接受前端塞的假答案
2. 幂等键：账号 + 应用 + request_id；冲突时必须核对材料、标准、模式、裁判配置，不能偷换
3. 冻结快照，建 `queued`，事务提交后再投 Celery（只投记录 ID）
4. Worker `claim`：条件更新认领 `running`，重复投递不重跑
5. 加载模型后结束读事务，再调模型；进度/结果另开短写事务
6. 保存时检查仍是 running **且** 提交后 15 分钟内；迟到结果写不进终态

`completed` = 报告生成完，是否通过看 `outcome` / `accepted`。Celery 投递失败、超时、执行失败 → `error`，已保存轮次保留。15 分钟截止**不会**打断正在阻塞的模型调用；Celery 软硬超时是另一层。

### 历史评分

裁判 Prompt 把任务文本当待审材料，其中「改规则、忽略标准」不当指令。Pydantic 解析：criterion_id 必须恰好 1..N。引用必须是 query/answer 子串；passed 必须有非空引用。

| verdict | score |
|---|---|
| passed | 1.0 |
| failed 部分满足 | 0.5 |
| failed 不满足 | 0.0 |
| insufficient_evidence | null |

有弃评时总体 score/pass_rate 留空，另给可评范围的分数。自称「文件已生成」不能当 passed。

`EVALUATOR_VERSION = answer-rubric-v3`。裁判与被测生产模型不是同一条运行图；具体是否换供应商取决于账号配置，代码强制的是「独立评分链 + 结构化输出」。

### 执行验收

`candidate_snapshot` 只取当前轮最近一次**不带工具调用**的回答，遇到新提问或未完成工具就停，不回退旧答。文件只接受该独立图的 UTF-8 文本 v2；格式异常或超限（回答 48k 字符、文件 50 个 / 合计 96k）直接终止，不裁剪凑合。

程序检查：`contains` 子串、`file_exists` 非空、`json_keys` 顶层字段。`evidence.ok` 只表示程序检查过，无额外规则时 ok 仍为真，**还要**裁判逐项打分。`candidate_hash` 只说明交付内容变没变。

原生 Rubric 管修订循环；平台在回调外持久化进度，防止框架吞掉回调异常后继续改。`EvaluationRound.accepts` 要求末轮通过、最终回答非空、哈希一致、程序检查过。

工具白名单由 `evaluation_tool_middleware` 限制；Rubric 适配集中在 `evidence_rubric_middleware`（对齐 Deep Agents 0.6.12）。

## 明确不保证

- 不是生产轨迹回归，没有 FakeLLM / TrajectoryAssert / Dataset 内容哈希锁版本
- 没有 Wilson/z 检验和发布门禁；没有影子流量
- 截止时间不杀阻塞中的 LLM 调用
- 引用存在 ≠ 外部事实为真
