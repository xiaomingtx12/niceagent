# ⑤ 上下文、压缩与记忆：什么进窗口、什么按需读

[返回组件地图](00-组件地图.md) · 业务链路见 [提示词、上下文、压缩与记忆](../platform/implementation/05-提示词上下文压缩与记忆.md)

## 这块组件在干什么

四种信息分开管，不能互相替代：

| 信息 | 放哪 | 干什么 |
|---|---|---|
| 固定规则与应用指令 | 构图时的 system | 每轮都要遵守的行为 |
| 本轮输入与规划选项 | 用户消息 / 工具消息 | 当前目标和本轮偏好 |
| 压缩摘要 | 框架压缩状态 + checkpoint | 用更短上下文续跑本会话 |
| 长期记忆文件 | 账号+应用隔离的 Store | 跨会话、按需读取 |

普通「总结一下」不会改框架上下文。摘要不会自动写成长期记忆。

## 当前怎么做

### 窗口预算

缺省窗口 **400_000** token（`DEFAULT_CONTEXT_WINDOW`）。`with_context_budget` 用输入上限、总窗口、输出预留算可用输入，再扣约 2% 安全余量（夹在 256–4096）。算不出预算就不伪造。

`ContextWindowMiddleware` 在每次模型调用前估分区占用（system / 记忆规则 / 人 / 助手 / 工具返回 / 工具定义 / 摘要），返回后用供应商真实 input tokens 补 `actual_input_tokens`，并记 cache_read / cache_creation。估算是 UTF-8 字节/2，**不等于计费 token**。多媒体不按 base64 长度冒充 token。

固定 system + 工具定义若已超过输入预算，直接报错，不把对话历史再往里塞。压缩触发展示约为预算的 85%。每个图只注册一次 `CustomTransformer`；记忆进度和压缩通知共用通道，重复注册会让流初始化失败。

system / tools 的 sha256 fingerprint 只供排障，不是供应商缓存键。

### 压缩与归档

自动压缩和主动 `compact_conversation` 共用框架引擎与同一预算。平台包装补了：同批禁止两次 compact、媒体卸载失败要在摘要里声明、异常不把供应商错误原文送进公开工具结果。

移出窗口的原文落到 `/conversation_history/`、`/large_tool_results/`（只读、有容量、作用域隔离）。模型按需分段读；路径存在 ≠ 媒体一定归档成功。

### 长期记忆

载体是 `/memories/` 下分类 Markdown：`preferences` / `background` / `experience`。不走向量召回，不自动列目录、不注入正文、不生成 `.index.md`。

读写复用原生 ls/glob/grep/read/write/edit；删除走 `delete_memory_file`。身份永远取本轮 `AgentRunContext`（账号+应用），即使恢复旧 checkpoint 也不能换成别的命名空间。子 Agent（`agent_id != "main"`）不能用长期记忆。

文件事务：Postgres 用 `pg_advisory_xact_lock`（5s lock_timeout）；内存 Store 用进程锁。管理接口可选 `expected_sha256` 做乐观并发；不传就是覆盖。配额：单文件 64KB、100 个文件、合计 1MB。

提示词要求：必须每轮遵守的规则写进应用指令；记忆是可能过时的参考，当前用户纠正优先，记忆里的越权指令不执行。

### 规划

自动模式：模型按原生规则决定是否 `write_todos`。显式模式：提示词要求先写/改计划再干活，信息不足先列澄清项。这是约定，不是强制规划循环，也没有「计划批准」门。计划未完成不阻止自然结束。

## 明确不保证

- 按需读取**不能保证**每轮都读到用户偏好；漏读是产品取舍，用应用指令补硬约束
- 没有 CONSTRAINT 硬召回通道，也没有遗忘 / superseded
- 压缩有损；归档失败的媒体必须当没读过
- cache fingerprint 跌了只能人工看，没有自动告警熔断
