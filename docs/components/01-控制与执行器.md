# ① 控制与执行器：一次图运行怎么收场

[返回组件地图](00-组件地图.md) · 业务链路见 [会话与运行生命周期](../platform/implementation/02-会话与运行生命周期.md)

## 这块组件在干什么

DeepAgents 编译出来的是一张 LangGraph。真正「跑一次、停一次、关资源」的是 `AgentExecutor`。它不创建 Run 记录，也不决定用哪份应用配置——那些在装配层已经做完。

每个执行器**只执行一次**。需要恢复时，Service 重新装配一个新执行器，沿用同一 `conversation_id` 的 Checkpointer。

## 当前怎么做

### 入口契约

`execute(message=...)` 和 `execute(resume=...)` 二选一。空字典仍按恢复处理，不会误发新用户消息。可选：

- `on_event`：工作台订阅规范化事件；微信兼容入口可以不传，只取最终结果
- `cancel_requested`：共享 `threading.Event`；不传则执行器自己建一个

`request_cancel()` 同时 set 取消信号并 `RunControl.request_drain("cancel_requested")`。未启动或已结束返回 False。

### 循环谁来停

主循环是框架的「模型 → 工具 → 模型」，模型不再请求工具时自然结束。平台另加硬上限（在中间件里，见 [③](03-装配与中间件.md)）：

| 上限 | 值 | 触达后 |
|---|---|---|
| 模型调用 | 50 / 本片段 | `exit_behavior="end"` |
| 工具调用 | 200 / 本片段 | `exit_behavior="continue"` |
| 模型瞬时错误重试 | 2 | 超时 / 连接 / 408·409·429 / 5xx |
| 只读工具重试 | 2，且仅 `ls/read_file/glob/grep` | TimeoutError / ConnectionError |

这不是金额或墙钟时间熔断，也不是跨 resume 片段合计的总预算。同步子图不自动继承这套中间件。

取消不是杀进程：流进入 drain，停止向订阅者交付新事件，但仍保存根图 `values`，避免子图快照盖掉最终回答。`GraphDrained(reason="cancel_requested")` 记为取消，其他 drain 记为失败。

### 结果怎么判定

优先级写死在 `execute` 返回前：

1. 执行或清理异常 → `failed`
2. 取消信号已 set → `cancelled`
3. 流上仍有 interrupt → `waiting_input`（只在这种状态返回 interrupts）
4. 其余 → `completed`

开启输出审核时，失败/取消会去掉 messages，避免半截回答进业务历史。用量来自 Observer 的本次片段累计，不是「最后一个模型调用」。

### 资源生命周期

执行器接管装配器交出的 `AgentRuntimeResources`。`finally` 里先把状态打成 `finished`，再 `close()`。运行中禁止 close。close 失败记 `CLOSE_FAILED`，**不自动重跑已经释放过的清理**——重复 close 成功路径可以，失败路径必须保留原异常。

进程共享的 Checkpointer / Store 不随单次运行关闭。

## 明确不保证

- 进程崩溃后，另一个进程不会自动用这个执行器接着跑（见 [⑨](09-恢复持久化与后台执行.md)）
- 正在阻塞的工具调用，只有工具自己响应 drain 才会马上停
- 50/200 限制按**本片段**计，恢复后的新片段重新计数
