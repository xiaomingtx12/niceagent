# ③ 装配与中间件：配置怎样变成一张可跑的图

[返回组件地图](00-组件地图.md) · 业务链路见 [身份、应用配置与模型装配](../platform/implementation/01-身份应用配置与模型装配.md)

## 这块组件在干什么

平台把「已授权的模型、工具、Skill、子 Agent」交给 Core。Core 不再按浏览器传来的资源 ID 查权限。装配失败必须清掉已经拿到的 Backend；成功后所有权交给执行器。

## 当前怎么做

### 装配链

```
Handler 身份
  → AgentDefinitionService（草稿 / 发布 / 内置助手 + 恢复指纹）
  → AgentModelService（默认模型、覆盖、失效回退）
  → AgentFactory.create_executor（本轮 AgentConfig + 附件字节）
  → AgentRuntimeAssembler.build
       工作副本 / Skill 投影 / Memory 路由 / Sandbox / Store / Checkpointer
  → build_deep_agent（提示词 + 平台中间件 + create_deep_agent）
  → AgentExecutor
```

Factory 里的 `connection_cache` 只在**一次装配**内复用连接查询（键含账号、供应商、连接 ID），不是跨请求共享编译好的图。共享图会连带共享回调和本轮资源。

`agent_assembly_timing` 分阶段记耗时（config / model / tools / subagents / skills / runtime.* / graph）。`total` 含多个阶段，不能把最后一条 graph 耗时当成首字延迟。

### 中间件顺序（不要重排）

`platform_middleware.py` 固定顺序：

1. 可选异步子 Agent 工具（插到最前）
2. `ReloadingSkillsMiddleware`：刷新本轮授权 Skill 元数据，`system_prompt=None`（官方 Skills 管提示词）
3. `ToolCallValidationMiddleware`：损坏的 tool_calls 直接拒绝，不猜参数执行
4. `ModelRetryMiddleware`：仅瞬时故障，最多 2 次
5. `ToolRetryMiddleware`：仅四个只读内置工具
6. `ModelCallLimitMiddleware(50, end)`
7. `ToolCallLimitMiddleware(200, continue)`
8. 可选 `AgentMemoryMiddleware`（只提供删除工具）
9. `ContextWindowMiddleware`（观测窗口，不负责压缩）
10. 可选 `UserInputMiddleware`（必须同时有 Checkpointer）
11. 有 Checkpointer 时再挂 `ConversationCompactionMiddleware`

DeepAgents 在平台链之前提供 Todo、Skills、Filesystem、SubAgent、摘要和工具调用补齐。工具调用补齐负责中断后的消息配对；平台校验负责拒绝无效调用，两者不能互相替代。

`memory=None` 传给 `create_deep_agent`：关闭框架自动记忆注入，保留按需文件工具。

### 通用子 Agent 的 Shell

框架默认 GP 子 Agent 会继承父工具（含 `execute`），但不继承平台中间件。`build_deep_agent` **总是显式声明** GP spec，并挂 `ShellExecutionMiddleware`：模型请求里藏掉 `execute`，执行入口再拒绝一次。自定义同步子 Agent 同样 `allow_execution=False`。

### 提示词前缀

`build_app_system_prompt`：平台规则 → 任务数据 → 规划约定 → 应用名/说明/业务指令 → 按开关追加记忆 / 异步任务 / 压缩 / Shell 路径。固定前缀不含应用变量、本轮选项、时间戳。本轮规划选项放在用户消息里，不改 system 头部。

## 明确不保证

- 发布不是单事务原子完成（见 implementation 01）；中途失败可能留下部分已提交变化
- 发布冻结的是绑定关系，不是远端 MCP、索引和模型权重的不可变快照
- 中间件限额是主图本片段的，不是全平台或父子合计预算
- 字符串顺序有利于供应商前缀缓存，**不保证命中**
