## 一张图：一次提问穿过哪些组件

```
入口 Handler（工作台 / WebApp / OpenAPI / 内部 Protocol）
        │ 解析 Account / End User / invoke_from
        ▼
② 运行编排  AgentExecutionService.start_run
        │ 锁会话 → 幂等 → 建 Turn+Execution → 提交后台线程
        ▼
③ 装配      AgentFactory → AgentRuntimeAssembler → create_deep_agent
        │ 已授权的模型/工具/Skill/子 Agent + 本轮 Backend
        ▼
① 控制/执行  AgentExecutor.execute
        │ stream_events → 中间件链 → 模型/工具循环
        │
        ├── ④ 工具/MCP/Workflow/Skill
        ├── ⑤ 上下文（system 前缀、窗口预算、压缩）
        ├── ⑤ 记忆（/memories/ 按需文件，不自动注入）
        ├── ⑥ 子 Agent（同步子图 / 异步 Protocol）
        ├── ⑥ ask_user interrupt（缺信息问人，不是高风险审批）
        └── ⑦ Workspace / Sandbox / deliver_file
        ▼
⑧ 事件与用量  Normalizer → EventBuffer（先实时、后合批落库）→ Observer
        ▼
⑨ 恢复与收尾  Checkpoint + executor_id 结算；waiting_input 可 resume
```

测评（⑩）不走这条生产图：独立 Celery 任务、冻结材料、隔离图。

## 几条读代码时一直成立的分工

1. **Handler 不跑图。** 入口只解析身份和协议；编排在 `internal/service/agent`，图执行在 `internal/core/agent_v2`。
2. **Core 不认数据库 Run。** 执行器只收 `message` 或 `resume`、事件回调、取消信号。表单幂等、占用、结算是 Service 的事。
3. **配置 / 业务事实 / 运行过程分开存。** 配置在 AppConfig 版本里；会话与用量在业务表；token/工具过程在 `agent_execution_event` + LangGraph checkpoint。不要用其中一个替代另外两个。
4. **进程内状态不是集群真相。** Tracker、事件 Hub、取消 Event、运行名额都绑在当前 Web 进程。多 worker 时「本机没线程」不能当成「Run 已死」。

## 建议阅读顺序

改一次请求怎么跑：① → ② → ⑧。  
改模型看不到工具 / 装配慢：③ → ④。  
改记忆漏读或缓存不命中：⑤。  
改表单、取消、子任务：⑥ → ②。  
改文件覆盖或沙箱：⑦。  
改进程重启丢任务：⑨。  
改评分误判：⑩。
