# 模型发现与参数配置

模型列表来自连接保存的发现快照。参数优先使用快照声明；目录未提供参数信息时，提供带通用编辑起始值的兼容参数。起始值不自动写入应用或发送。已删除旧静态模型 YAML、排序文件和自动发送的五参数默认模板。
供应商连接目录 `providers.yaml` 与图标继续保留，用于连接类型、默认服务地址和发现端点。

## 使用

1. 在设置的模型连接中发现并启用模型。
2. 模型目录支持 `parameters` 对象列表或 `supported_parameters` 名称列表。未返回参数或返回 null 时，编排页开放通用兼容参数并标记来源；默认不发送任何可选参数。明确声明的空列表或手工禁用的参数不自动补充。
3. 在模型列表「编辑能力」下补充最大上下文和参数定义。未知范围留空。
   对话和补全模型未提供最大上下文（包括旧快照的 0）时使用平台默认 258000 token（258k）；标记为平台默认的旧窗口随默认值更新，供应商声明值和手工配置优先。连接页容量仅展示最大上下文，发现的输入、输出限制仍由后端保留并校验。
4. Agent 与工作流共用「模型设置」表单。可选参数默认使用服务默认值，勾选「自定义」后才发送。
   温度、最大输出 token 为常规参数；top_p、top_k 等放在高级参数中，已有覆盖会自动展开。思考等级独立显示为下拉选择，不使用自由文本输入；不提供工作负载预设。
5. 切换模型后，不支持的配置需显式移除；越界参数显示错误，调整后保存。关闭弹窗不会保存。
6. 工作流新建模型节点先选择当前连接中的模型，不再默认选择旧模型。发布版本需重新发布才更新配置。

## 参数边界

当前 OpenAI-compatible 适配器支持配置 temperature、top_p、top_k（采样）、presence_penalty、frequency_penalty、最大输出、reasoning_effort、seed 和单条 stop。
这份适配器白名单不表示模型默认支持。发现或手工声明优先；对没有参数信息的对话模型，允许用户显式设置这些兼容字段，具体支持情况由当前服务决定。兼容定义使用下文的通用编辑范围与起始值，只有用户保存的覆盖值才发送。
不接受通过用户参数/旧 attributes 注入 api_key、base_url、model_kwargs、extra_body 等连接或传输配置。

统一配置名为 `max_output_tokens`；连接定义的 `api_name` 决定实际发送 `max_tokens`、`max_completion_tokens` 或 `max_output_tokens`。
精确输出字段通过 SDK `extra_body` 发送，防止 ChatOpenAI 自动重命名。测试捕获真实 SDK HTTP JSON 验证。

采样 `top_k` 为整数，经 SDK `extra_body` 发送为 JSON 顶层字段，与精确输出字段和非标准思考字段合并。兼容模式允许显式设置；范围、默认值和 -1/0 等特殊值以当前服务声明为准，不从供应商名称推测。兼容输出字段使用 `max_tokens`，服务要求其他字段时通过连接参数定义设置 `api_name`。

思考级别统一保存为 `reasoning_effort`。编排页提供「服务默认」和模型声明的枚举；兼容模式提供 low / medium / high，只有参数名而没有枚举时也使用这三个通用选项。服务支持的具体等级仍可在连接参数定义中调整。既有非通用级别保留可见，不静默删除；明确枚举之外的旧值需重新选择。连接能力编辑器可选择已经确认的级别或添加供应商自定义级别。
服务思考字段可配置为 `reasoning_effort`、`thinking_level` 或字符串类型的 `thinking`；后两者通过 `extra_body` 发送并与输出上限合并。这不适用于需要对象类型 thinking 或独立思考预算的协议。
未勾选自定义思考级别时不发送该参数，由服务采用默认行为。多个旧思考字段值冲突时，需显式清空冲突值再保存。

已有快照中保存的枚举继续视为该快照的声明；旧版本自动补充的 low / medium / high 与用户确认值没有独立来源标记，需重新发现或手工核实，不批量改写。

参数的类型、范围、枚举和必填约束由后端统一校验。默认值只给必填字段补值，可选参数的默认值不自动发送。
`input_token_limit` 仅映射输入上限，不当作完整上下文容量；上下文查看和 SDK profile 都来自当前发现快照。

## 通用编辑起始值

Agent 应用和工作流 LLM / 意图分类节点共用模型设置。所有可选参数初始均使用服务默认；以下值仅用于用户启用自定义时填入编辑控件。供应商或连接声明的默认值和范围优先。

| 参数 | 自定义起始值 | 通用兼容范围 |
| --- | --- | --- |
| temperature | 1 | 0–2 |
| top_p | 1 | 0–1 |
| presence_penalty / frequency_penalty | 0 | -2–2 |
| 最大输出 token | 8192，受已知输出上限和上下文容量约束 | 正整数，已知模型上限优先 |
| top_k | 启用时以 40 起填 | 整数，具体范围以服务声明为准 |
| 随机种子 / 停止序列 | 默认不设置 | 整数 / 单条字符串 |
| 思考等级 | 服务默认 | low / medium / high 或当前模型声明的选项 |

兼容参数来源标记为 `compatible`，加载时按当前通用定义重新生成，避免旧快照的起始值阻止更新容量。已保存的应用参数不自动重写；手工定义和目录声明不受通用定义覆盖。

推理等级名称不代表不同模型间相同的算力、价格或延迟。若服务在某种推理模式下禁用采样参数，请按其协议取消不兼容的采样覆盖；当前参数契约只校验单字段，不表达条件互斥。

同步子 Agent 未覆盖模型时继承主 Agent 实例及参数；独立模型使用 `model`、`model_provider`、`model_connection_id` 保存模型名、供应商和连接，保存与运行均校验连接归属及模型启用状态。旧 `provider/model` 引用仍可读取，按第一个斜杠拆分；同名模型存在多个连接时必须重新选择具体连接。独立模型覆盖暂不提供单独的参数编辑，使用所选连接的模型默认参数。需要独立推理强度的子任务，可配置为单独的已发布 Agent，在该应用中配置模型参数后重新发布。远程子 Agent 的模型配置由目标服务管理。

## 工作台推理选择

工作台输入框附近提供当前模型已声明的推理等级和「Agent 默认」。优先级为任务选择、Agent 编排默认、服务默认。每次发送携带任务选择，后端在创建消息前校验；只覆盖运行参数，不改写 Agent 草稿或发布配置。选择保存在已有 Run JSON 快照中，重新打开会话可恢复最近选择，表单中断恢复沿用原运行选择，无需数据库迁移。

选项通过当前会话的授权状态接口返回，兼容编排调试、平台任务、发布 Web App 和辅助 Agent，不向访客返回连接标识或密钥。未启用推理参数的模型不展示选择器；已启用但没有枚举时与编排页一致使用通用三个等级。运行中和等待表单时禁用调整。切换任务或修改编排模型会重新读取选项，失效等级回退 Agent 默认，后端始终以当前参数契约校验。

## 检索 top-k

知识库的 `retrieval_config.k` 表示召回文档片段数，与模型采样 `parameters.top_k` 完全独立，不把检索 k 传给模型 SDK。

| 场景 | 检索 k 调优起点 | 配置位置 |
| --- | --- | --- |
| 精确事实查询、短 FAQ | 3–4 | Agent 知识库设置或工作流知识库检索节点 |
| 常规知识问答 | 4（当前默认） | 同上 |
| 跨文档比较、信息综合 | 6–8 | 同上，结合分段长度和上下文预算 |

检索效果差时先检查查询、分段、检索策略和阈值，不直接用更高推理强度补偿缺失证据。对固定样例集比较答案正确率、引用命中率、端到端延迟和 token 用量，再逐项调整。调整采样 top-k 时先固定其他采样参数，top-k=1 不保证跨供应商或多次运行完全确定。

协议参考：[OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning)、[LangChain OpenAI-compatible endpoints](https://docs.langchain.com/oss/python/integrations/chat/index#chat-completions-api)。本平台目前使用 Chat Completions 的字符串字段；Responses API 的 `reasoning.effort` 对象不是当前传输格式。

## 旧配置

旧发现快照没有 `parameter_contract_version=2`，其自动五参数模板不作为服务能力声明，改用通用兼容定义，模型仍可选，未自定义参数仍不发送。
已有应用的温度、输出上限、top_p、惩罚等白名单值保持可见、可编辑和可保存，不因为目录缺少参数信息而要求删除。明确声明列表之外的字段和非白名单字段仍需清理。
旧 `max_tokens`/`max_completion_tokens` 在保存时归一化；不同别名值冲突时拒绝静默取值。
未选择、停用或缺失的模型保留原引用，不自动换成另一模型。同名模型存在多个连接时须明确选择连接。
上述处理不执行数据库迁移、不批量重写存量数据。再次发现模型会保留同一连接中明确标为手工的参数和容量设置。

- 类型检查：`npm run type-check`
- Python 语法检查：`python -m compileall -q internal/core/language_model`
- 功能验收：目录无参数的模型应展示通用参数，保留旧值并允许保存；已声明参数的模型仍执行其范围和枚举校验；取消编辑不修改配置。按用户要求，功能测试由用户执行。
