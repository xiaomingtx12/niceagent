# 应用沉淀

这一节和“资源导航”“方法与复盘”都不一样。

这里不是在点评别人的资料，也不是在写抽象方法论。

这里更关心另一件事：我手搓实现几个 Agent 项目之后，怎么把它们拆回产品、系统和实现，尤其是那些能复用到下一次实践里的工程化细节。

## 这一栏现在优先放什么

- 手搓 Agent 项目的工程化拆解
- 核心能力的实现路径和取舍
- 能复用到下一次项目里的实践复盘
- 从 demo 走向可交付系统时的关键问题

## 先看什么

- [Dify 型平台拆解](./dify-type-application/)：这一组先从一个类 Dify 的 Agent 开发平台开始，重点拆工程模块、实现路径和复盘
- [怎么把一篇 AI 应用文档写得真正有用](./what-i-want-to-write-here.md)：这是我给自己定的写法标准，后面每篇工程笔记都可以按它校验

## 这里不放什么

- 单条资源的收录说明
- 纯粹的学习流水账
- 只讲概念、不碰实现的空泛总结
- 没有工程判断、只有结果描述的项目记录

## 这一栏的输出标准

- 不只列功能，还要说清它是怎么实现出来的
- 不只写结果，还要拆出中间的工程路径和约束
- 不只谈产品想法，还要落到状态、权限、预算、异步任务、观测性这些系统问题
- 不只证明“能做出来”，还要写清边界、成本、代价和后续维护方式

## 我为什么单独开这一栏

我越来越觉得，只会“看资源”是不够的。

真正能把人往前推的，往往是自己开始把问题拆成产品、系统和实现三个层面，并且真的把它做出来之后留下来的东西。这个栏目就是给这些工程化笔记留位置的。
