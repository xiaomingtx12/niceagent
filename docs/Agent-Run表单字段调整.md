# Agent Run 表单字段调整

日期：2026-09-15。依据：[Agent 最小交互业务约定](Agent-最小交互业务约定.md)。

本文记录首批调整；最终表名、运行选项去重及附属引用改名以 [会话与执行表定案](Agent-会话与执行表定案.md) 为准。下文旧表名用于说明尚未迁移的数据来源。

本次修改 ORM 和相关前后端读写；未生成迁移、未执行数据库升级或数据回填。表名和表关系沿用现有结构，Conversation、Message、Submission、Event 的数据库列不变。

## 字段变化

| 原字段 | 新字段 | 类型和默认值 | 用途 |
| --- | --- | --- | --- |
| `interaction_state.pending_inputs` | `agent_run.pending_inputs` | JSONB 数组，非空，默认 `[]` | 当前批次待填表单；仅等待填写时公开，接受答案或结束本轮时清空。 |
| `interaction_state.input_history` | `agent_run.input_history` | JSONB 数组，非空，默认 `[]` | 已确认的问题、字段说明及答案；保留历史展示和后续模型调用所需语义。 |
| 其余取消重开状态 | 无 | 无 | 取消后不再维护可重开副本和重开回执。 |
| `interaction_state` | 移除 | 无 | 两项实际业务数据改为直接读写列，减少字典合并和隐式字段归属。 |

按最终 Model 约定不增加 JSON 类型 CHECK；待填表单和提交内容沿用业务层校验。Submission 仍按 `(run_id, input_batch_id)` 保存已接受答案和回执，不能用 `input_history` 替代提交去重。

`invocation_snapshot` 保留完整调用参数，恢复继续检查身份和配置指纹。`state_snapshot` 仅写入 `messages/todos/files/async_tasks`；消息限制为当前轮，历史从 Message 读取。表单状态不再经由展示快照写回。

## 配套行为变化

- 正常 `ask_user` 仍可多次暂停，同批提交只接受一次，继续原 Run。
- 提交时在同一事务中追加 `input_history`、清空 `pending_inputs`、保存 Submission、认领新执行标识。
- 已接受批次先按授权会话和入口查回执；开始下一轮后，旧批次的迟到重试仍返回原接受结果，不恢复旧 Run。
- 等待填写时取消直接清空表单并写入取消状态和事件；前端移除重新填写入口，旧重开命令返回拒绝。
- 取消后允许原会话开始新一轮；仍需等待本地执行片段退出，不绕过会话占用和旧执行写入校验。
- 下一轮通过普通消息字典调用图，只有表单提交使用 `Command(resume=...)`。当前安装的 LangGraph 新输入路径丢弃旧 checkpoint 未完成调度，DeepAgents 的 `PatchToolCallsMiddleware` 补齐取消工具回执；保留会话消息，不删除整个 checkpoint。依赖升级时应重新验证这条行为。
- 待填页面停止后可能没有活动 SSE，前端重新加载已确认状态以清除旧表单；执行中可编辑普通消息草稿，发送仍受执行状态限制。

## 落库前的数据保留要求

自动生成的“新增两列、删除旧列”不包含 JSON 数据搬移，不能直接据此删除旧列。

1. 在维护窗口内停止旧代码写入，并等待活动执行退出；保留数据库备份。有效的等待填写记录需要保留原 Run、调用参数、提交记录和 checkpoint。
2. 新增 `pending_inputs`、`input_history` 两列。
3. 将旧 `interaction_state.input_history` 数组完整复制到新列，包括已完成、失败和取消的记录。键不存在时使用空数组；类型异常应先核实，不能静默丢弃。
4. 仅对 `waiting_input` Run 搬移旧 `pending_inputs` 数组；其他状态新列置空。等待状态缺少有效表单时先核实，不应制造空表单却仍占用会话的记录。
5. 旧已取消表单不恢复为待填；历史事件、Submission 和已确认问答保留。旧 `state_snapshot` 多余键会在读取时被屏蔽、下次快照更新时按白名单收敛。
6. 核对待填批次 ID、已确认历史和 Submission 数量未丢失后，删除旧业务 CHECK 与 `interaction_state` 列，不新增数组 CHECK。
7. 部署配套前后端，按最小交互文档验收。新 ORM 在数据库尚无新列时不能直接运行；旧代码也不能继续向已移除的列写入。

上述为维护者生成和审阅迁移时的数据映射要求，不是可执行迁移。按仓库约定，本次没有创建迁移文件，也没有自动回填线上或本地数据库。
