# 项目串讲与模拟面试

## 三十秒项目介绍

NiceAgent 是面向知识问答、资料分析、内容生成和文件处理的智能体平台。用户可以在线配置模型、工具、Skills、知识库、工作流和子 Agent，通过 WebApp 或开放 API 使用。我重点准备的后端实现包括从自建 LangGraph Agent 到 DeepAgents 的演进、任务暂停恢复、流式续传、上下文与记忆、沙箱和文件交付，以及输出评估验收。个人负责范围按实际经历补充。

## 三分钟讲解顺序

| 时间 | 讲什么 | 要落到的具体点 |
| --- | --- | --- |
| 0:00～0:30 | 业务能力与演进。 | 用户怎样配置和使用；为什么扩展到多 Agent 和文件任务。 |
| 0:30～1:00 | 装配边界。 | 入口身份、应用定义、授权能力、Core 构图与框架职责。 |
| 1:00～1:40 | 一轮执行的控制与展示。 | ask_user、Checkpoint、提交幂等、执行权；SSE 与游标恢复。 |
| 1:40～2:20 | 上下文和执行资源。 | 动静分离、按需记忆；工作副本、沙箱租约和显式交付。 |
| 2:20～3:00 | 可组合能力与质量。 | RAG 和工作流工具化；评估裁判、规则核验和证据一致性。 |

开场不必背完 8 条。讲清平台主链路后，让面试官选模块深入，再用对应文档的一分钟口述展开。

## 一个跨模块讲解案例

场景：用户要求根据知识库资料生成分析报告，缺少时间范围，最终交付文件。这是讲解用案例，不代表已经运行并验证了该具体任务。

1. 平台解析身份与应用配置，装配检索工具、报告 Skill 和所需子 Agent。
2. Agent 调用 ask_user 询问时间范围；图中断保存，平台持久化等待表单。
3. 用户提交后经过校验和幂等处理，同一任务以新执行片段恢复。
4. Agent 检索资料，需要分工时委派子 Agent；模型、工具和状态事件经 SSE 交付。
5. 如果只生成 Markdown，可以在本地工作副本完成；若需要执行脚本，首次命令触发远程沙箱初始化。
6. 沙箱准备工作文件和授权 Skill，Agent 生成产物并显式保存到 COS。
7. 过程中如果页面刷新，按已提交快照及后续事件恢复展示，不重跑 Agent。
8. 上下文过长时使用框架压缩及归档；确需跨会话复用的信息按需写入长期记忆。
9. 任务结果与业务终态提交后结束展示，运行资源被释放或归还。
10. 后续可对保存的回答发起独立历史评分；隔离执行验收是另一种模式，不把它说成原任务真实工具链的全量回放。

## 跨模块高频追问

| 问题 | 回答方向 | 对应材料 |
| --- | --- | --- |
| 为什么迁移到 DeepAgents 后还有 LangGraph？ | DeepAgents 复用 LangGraph；业务工作流也继续用图执行。 | [架构装配](03-Agent架构演进与在线装配.md) |
| SSE 恢复和任务恢复有什么区别？ | 一个恢复展示，一个恢复图执行；两种快照职责不同。 | [任务](04-任务管理与交互恢复.md)、[事件](05-流式事件与断线续传.md) |
| 图能恢复，临时文件为什么不能保证保留？ | Checkpoint 保存状态，临时目录另有生命周期；要显式保存。 | [沙箱](07-工作区沙箱与文件交付.md) |
| 同会话只跑一个任务，为何还有文件并发？ | 持久化 Workspace 按账号和应用共享，不同会话可改同一路径。 | [沙箱](07-工作区沙箱与文件交付.md) |
| 子 Agent 可以直接使用父 Agent 的全部能力吗？ | 自定义子 Agent 显式装配授权工具与 Skill，Shell 单独限制。 | [架构装配](03-Agent架构演进与在线装配.md) |
| 使用 Skill 就必须启动沙箱吗？ | 阅读规则不需要；执行脚本等操作才触发。 | [沙箱](07-工作区沙箱与文件交付.md) |
| 长期记忆、历史归档和知识库有什么区别？ | 分别对应跨会话经验、会话历史和外部资料检索。 | [上下文](06-上下文工程与长期记忆.md)、[RAG](08-在线知识库与混合检索.md) |
| SSE 发了事件但数据库没保存怎么办？ | 当前有异步尾部窗口，进程崩溃不保证零丢失；终态单独控制。 | [事件](05-流式事件与断线续传.md) |
| 文件存 COS 就能保证一致性吗？ | 正文存储、数据库版本校验和补偿清理各有作用。 | [沙箱](07-工作区沙箱与文件交付.md) |
| 并行和条件分支为什么不能同样汇聚？ | 一个必须等全部，一个只执行被选择分支。 | [工作流](09-可视化工作流引擎.md) |
| 裁判说通过就能交付吗？ | 还要检查程序证据、候选哈希、最终内容及验收状态。 | [评估](10-Agent评估与执行验收.md) |
| 用量统计有没有分布式 tracing？ | Callback 累计调用与 Token，不保存完整 Span 树。 | 下方补充亮点。 |

## 可作为补充的后端亮点

用量观测通过 LangChain Callback 累计模型/工具调用和 Token，并按模型归类。业务执行片段将用量与结果在受执行权保护的事务中结算，结束后拒绝迟到回调。当前 Observer 不维护完整 Span、父子调用树或通用 APM，因此适合称为运行用量统计。

装配优化包括本轮模型连接记录复用、工具批量校验、API/MCP 批量查询、空引用跳过以及同轮相同 Skill 文件集投影复用。它们减少重复工作，但不等于模型实例跨参数共享或永久缓存授权数据。入口见 [AgentFactory](../../internal/service/agent/agent_factory.py) 与 [运行观测](../../internal/core/agent_v2/observability/run_observer.py)。

## 必须能讲清的边界

- 实时事件、取消信号和沙箱池含进程内状态，当前不能描述为任意多 Worker 自动接管。
- Checkpoint 不保证任意外部副作用恰好一次，也不是所有临时文件的备份。
- 稳定前缀为缓存创造条件，不能未测量就说 Token 成本下降某百分比。
- Daytona 池按会话复用；工作目录重置不等于整个远程环境完全重建。
- 关键词召回当前不是 BM25，融合也不是已实现独立 reranker。
- Rubric 来自框架，平台实现适配、证据和业务任务；修订不更新模型权重。
- 当前代码能力、数据库部署状态、功能验收和真实生产效果应分别陈述。

## 建议采集的指标

下面是面试前可执行的采集计划，本系列没有运行这些实验，也没有填入假数据。

| 模块 | 指标或材料 | 对比条件 |
| --- | --- | --- |
| 装配 | config/model/tools/skills/runtime 各阶段耗时。 | 相同配置的首次与后续请求，区分 SDK 初始化和远程沙箱。 |
| 任务 | 重复提交是否复用原 Run、重复恢复次数、取消完成时间。 | 相同 message_id/表单批次，区分模型阻塞和平台收尾。 |
| 事件 | 首字交付时间、批大小、写入次数、恢复耗时。 | 相同事件规模，区分实时尾部与数据库前缀。 |
| 上下文 | 输入 Token、缓存 Token、压缩次数和摘要延迟。 | 相同模型、工具定义、消息序列及预算。 |
| 沙箱 | 新建/复用耗时、Skill 原始/上传字节、空闲回收。 | 相同文件集和凭据，分别测实例与文件部署。 |
| RAG | Recall@K、MRR、检索延迟。 | 有标注查询集，比较三种策略并固定模型和分段。 |
| 工作流 | 节点耗时、条件/并行两种汇聚结果。 | 最小可解释拓扑，另测复杂分支边界。 |
| 评估 | 裁判与人工一致性、弃评比例、修订轮数和用量。 | 冻结相同标准与样本，分别看历史评分和执行验收。 |

## 四十五分钟模拟面试安排

1. 3 分钟讲平台业务与架构演进。
2. 7 分钟沿一次请求说明身份、配置、图装配和能力授权。
3. 10 分钟推演重复提交、等待表单、取消冲突及断线重连。
4. 10 分钟说明工作区路由、沙箱租约、Skill 部署与文件版本。
5. 8 分钟任选上下文、RAG、工作流或评估深入。
6. 7 分钟讨论现有限制、后续设计和个人贡献。

回答自检：能否说出具体场景、函数入口、状态/事务边界、失败行为和取舍？如果只能复述框架名，回到对应模块的实现链路。真实故障案例应使用自己遇到并能复现的经历；本系列推演不应包装成真实线上事故。
