# 任务管理与交互恢复：面试准备

## 简历主张与编写思路

先写任务生命周期，再写交互恢复，最后解释并发保护。核心问题是 Agent 缺少必要信息时如何暂停，用户回答后如何继续同一个任务，以及重复提交、取消和迟到写入怎样处理。

## 一分钟口述

我把会话、一轮问答、业务执行和后台执行片段分开管理。Agent 需要信息时调用 ask_user，工具通过 interrupt 提交表单，Checkpoint 保存图状态；平台将业务执行保存为 waiting_input，并持久化待填表单。用户提交后，平台校验字段、批次和配置一致性，保存幂等记录，认领新的执行标识，再用 Command(resume) 继续原任务。同一会话的关键检查与更新用行锁串行化，结果写入还要校验 executor_id。取消采用先记录请求再通知执行器，等待输入的任务可以直接取消。

## 先区分几个身份

| 概念 | 作用 |
| --- | --- |
| Conversation | 持续对话及其稳定归属。 |
| ConversationTurn | 一轮用户输入、回答及累计用量。 |
| AgentExecution / run_id | 一轮可等待、可恢复的业务任务；补充答案不新建任务。 |
| executor_id | 当前后台执行片段的写入资格；恢复会分配新标识。 |
| Input Batch | 这一批需要一起回答的表单，依据中断 ID 集合识别。 |
| Submission | 已接受答案与回执，用于重试去重。 |

会话、Run、Checkpoint thread_id 和 SSE 连接不是同一个生命周期。一次断开 SSE 不代表任务停止；一次等待输入也不等于删除会话。

## 启动到恢复的链路

1. start_run 锁定会话，按 input_message_id 检查重复输入，再检查会话是否被活动或等待输入任务占用。
2. 在事务内创建问答与执行记录，登记本地执行；提交成功后投递后台线程，避免后台读取未提交记录。
3. ask_user 构造并校验表单，通过 interrupt 暂停图。Core 返回中断信息，平台保存 waiting_input 和 pending_inputs。
4. submit_answers 按固定顺序先锁会话、再锁执行，先查是否已有相同批次的 Submission。
5. 已接受且答案相同则返回原回执；答案不同则拒绝。新提交检查当前等待状态、完整批次、字段合法性、旧执行已释放与配置指纹一致性。
6. 同一事务保存答案历史和 Submission、清空待填表单、置 running 并认领新的 executor_id。
7. 提交后重新装配执行器，调用 execute(resume=...)，内部使用 Command(resume)，不新增 HumanMessage。
8. 执行片段结束，在执行权校验和行锁保护下提交回答、用量、任务状态与终态事件，并释放执行权。

Checkpoint 保存框架状态；业务表保存权限、表单、提交记录和状态；临时工作目录由本轮资源管理。恢复要求这些边界配合，Checkpoint 不会保存本地目录或远程进程快照。

## 三种保护各自防什么

| 机制 | 示例 | 实际作用 |
| --- | --- | --- |
| 会话/执行行锁 | 两个请求同时发现会话空闲。 | 将检查与创建放在一个受保护事务内，避免同时占用。 |
| 提交幂等 | 前端超时后重发同一条消息或表单。 | 相同身份与内容返回原结果，不重复创建或恢复。 |
| executor_id 校验 | 已结束执行 A 的迟到写入抵达，而任务已由 B 恢复。 | A 无写入资格，不能覆盖 B 或再次累计用量。 |

行锁只覆盖数据库关键操作，不持有到模型推理结束。不同幂等 ID 的相同文本是两次不同输入，不能声称所有内容相同的请求都会去重。

## 取消与恢复的竞态

| 操作先后 | 结果 |
| --- | --- |
| 等待输入时取消先提交 | 任务取消、清空待填表单，后续新答案不能恢复该任务。 |
| 表单恢复先提交 | 任务已成为运行态，随后取消走运行中的停止请求。 |
| 结果先完成提交 | 取消重新读取状态，不能把已完成结果覆盖为取消。 |
| 运行中收到取消 | 先持久化 cancel_requested_at，再通知本地执行器；待实际退出后结算。 |

外部模型或工具调用可能仍在进行，停止请求不等于立即杀死调用，也不会撤销已经发生的外部副作用。已接受表单的迟到重试可能返回原回执，这不代表重新执行。

## 典型追问与回答要点

**为什么不能只靠前端禁用按钮？**

网络重试、多标签页或直接 API 调用都能绕过按钮。重复判断必须落在后端，并和任务创建、答案保存处于受保护的事务边界。

**恢复为什么重新装配执行器？**

一次执行器只执行一次并负责释放本轮资源。暂停会释放独占资源；恢复沿用业务任务和 Checkpointer 会话身份，重新建立模型、Backend 等运行依赖。

**Checkpoint 能保证外部工具只执行一次吗？**

不能。图中断和恢复涉及节点重入，interrupt 之前的逻辑应避免不可重复副作用。发送消息、写外部系统等工具仍需要自己的幂等策略或明确审批边界。

**等待期间修改应用配置会怎样？**

平台检查定义指纹，配置变化时拒绝直接恢复，避免旧中断状态在新工具或模型定义下继续。不能把它描述为自动保留完整旧运行环境。

**进程重启会自动接管未完成任务吗？**

当前本地执行跟踪和控制依赖进程，提供孤儿状态收敛，但没有实现通用分布式 Worker 接管。Checkpoint 可用不代表任意中断的运行都能自动恢复。

## 面试前准备

准备连续重复发送、重复提交表单、取消后提交旧表单三个演示。每个演示说清业务状态、回执和是否新建 executor_id。不要把浏览器重连成功当成业务恢复成功。
