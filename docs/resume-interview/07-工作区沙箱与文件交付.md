# 工作区、沙箱与文件交付：面试准备

## 简历主张与编写思路

这一条必须覆盖「路由、生命周期、Skill 部署、产物交付」。只写沙箱名称会遗漏工程工作，只写上传文件也不能体现创建、复用和回收。主线是 Agent 在哪里操作、能访问什么、什么时候产生远程资源、最终保留哪些文件。

## 一分钟口述

每轮 Agent 先获得本地临时工作区，CompositeBackend 将工作区、Skills 和记忆等路径路由到对应存储。使用远程 Provider 时，普通问答、阅读 Skill 和工作区文件操作不立即创建沙箱，首次执行命令等操作才初始化。Daytona 通过凭据和会话身份取得独占租约，可以在 TTL 内复用实例；复用前清理工作目录并重新部署本轮文件及授权 Skill。Skill 根据大小和压缩收益选择打包上传，校验解包路径并保护只读目录。产物由 deliver_file 显式保存至 COS，平台版本校验防止覆盖新内容。结束时统一释放资源，可复用实例归还池，超时、淘汰或失效后销毁。

## 三种文件位置

| 位置 | 生命周期 | 用途 |
| --- | --- | --- |
| 本轮本地临时工作区 | 随执行片段创建和清理。 | 远程启动前读写文件、准备附件和已加载材料。 |
| 沙箱工作副本 | 本轮独占；复用实例时相关目录重新初始化。 | 文件工具和脚本操作同一份远程数据。 |
| 持久化文件库 | 跨会话保留，正文在 COS、元数据和版本在数据库。 | 预览、下载、后续任务按需加载。 |

Workspace 的当前持久化作用域由账号与应用生成，因此不同会话可能加载同一文件。沙箱池按会话隔离，与持久化文件共享范围不同。

## 路由如何组织

运行时用 CompositeBackend 按路径前缀分配操作。没有沙箱时 /workspace/ 指向本地 FilesystemBackend；有沙箱时，根路由指向执行 Backend，较长的 Skill、Memory 和历史路径优先命中各自 Backend。远程 LazySandboxBackend 在启动前又将 /workspace/ 操作转给本轮本地副本。

Skills 使用授权投影，Memory 使用 Store，历史归档只读。路由决定数据从哪里读写，权限决定是否允许；仅靠文件工具权限不能限制 Shell 命令，因此还需要沙箱和子 Agent Shell 策略。

## 创建、复用、归还、销毁的完整链路

### 1. 装配时只绑定工厂

AgentRuntimeAssembler 创建工作副本和 Skill 投影，工厂为 Daytona/LangSmith 返回 LazySandboxBackend。此时不连接远程实例，也不上传 Skill。未启动沙箱时，工作区内读写和附件准备都使用本地副本。

### 2. 首次需要执行环境时初始化

execute 或访问必须由远程处理的路径触发 _ensure_backend。RLock 合并同轮并发首次调用，避免重复创建。初始化失败被记录，本轮后续调用不会再次盲目创建。

### 3. Daytona 申请会话独占租约

池键为「hash(API URL + API Key)，hash(账号 + 应用 + 会话 + Agent)」。

| 池状态 | 动作 |
| --- | --- |
| 无实例 | 先占会话槽位，锁外调用远程创建。 |
| 空闲且未过期 | 标记 busy、推进租约代际，复用实例。 |
| 已 busy 或失效 | 拒绝同会话再次使用，避免共享工作目录。 |
| 已过期 | 淘汰旧实例，重新创建。 |

慢网络创建不持有全局池锁，因此不阻塞其他会话申请。该池在 API 进程内，并不是跨 Worker 的分布式资源池。

### 4. 准备本轮工作区和 Skill

复用时清理 workspace、skills、subagent_skills，再创建目录。上传本轮本地已有的文件和本轮授权 Skill，初始化全部成功才置 _ready=True。

只迁移已经加载或生成的文件，不全量下载持久化文件库。清理上述目录不等于重建整个操作系统环境；不能宣称复用后是完全无残留的新容器。

### 5. 运行并显式保存产物

远程启动后，文件工具和 Shell 统一使用远程工作副本。deliver_file 通过 Backend 读取指定文件，再写持久化存储。没有启动沙箱时，同一工具直接从本地副本读取并保存到 COS。

### 6. 退出时归还或淘汰

AgentExecutor 在 finally 中关闭 AgentRuntimeResources。先释放或归还 Backend，再清理仓储会话、Workspace 和 Skill 临时目录。相同 Backend 按实例去重关闭，单项失败继续清理其他资源并汇总错误。

Daytona close 根据 _ready、失效标记、池状态和 TTL 决定是否回池；普通任务执行失败不必然等于销毁，初始化失败则直接淘汰。归还资源不扫描文件、不自动上传产物。

### 7. 最终销毁的触发条件

| 条件 | 当前处理 |
| --- | --- |
| 空闲超过 TTL | 默认 600 秒，定时回收；再次 acquire 也核对过期时间。 |
| 空闲池超容量 | 默认最多 3 个，优先淘汰最久未使用者。 |
| 会话删除 | 空闲实例立即失效清理；使用中的实例归还时清理。 |
| 初始化失败 | 不进入可复用状态，释放远程资源。 |
| 正常进程退出 | atexit 清理；创建中的资源返回后检查池状态。 |
| 进程异常退出 | 依赖 Provider 自动停止/删除配置兜底，不能保证 finally 执行。 |

定时器回调检查对象身份、busy 和 generation，防止旧定时器误删已经重新被使用的租约。远端优先 delete，旧客户端不支持时退回 stop；失败记录日志。这个会话池策略是 Daytona 实现，不应套到所有 Provider。

## Skill 压缩上传的技术细节

只打包已授权的内存文件内容，不重新扫描宿主目录。文件总量达到 64 KiB 且 ZIP 至少节省 10% 时，采用单包上传；否则直接上传文件。阈值是选择策略，不是实测平均收益。

解包前校验路径属于 skills/subagent_skills，拒绝跨目录、重复或非规范路径，检查目标链中的符号链接及文件类型。标准库解包后清理临时 ZIP，再保护 Skill 目录只读；工作区继续可写。只读 Skill 目录不等于脚本没有副作用，脚本执行仍受执行环境和工具权限约束。

## 为什么需要显式交付和版本校验

临时脚本、缓存和中间结果不应全部持久化，因此资源关闭不自动同步工作目录。list_saved_files 只查元数据，load_saved_file 按需加载单文件并记录版本，deliver_file 显式交付。

两个会话都加载 report.md 的版本 3：A 保存后成为 4，B 携带版本 3 覆盖时被拒绝。即使保存操作不在同一毫秒发生，旧副本也会造成丢失修改。B 可以另存，或将最新文件加载到另一副本后重新处理。

未加载目标只允许新增；加载过的副本使用对应版本覆盖。COS 存正文，平台数据库控制版本。存储先上传唯一对象，再提交元数据；元数据失败时尽力清理新对象，成功后尽力删除旧对象。这是补偿清理，不是 COS 与关系库的跨系统原子事务。

## 典型追问与回答要点

**读取 Skill 会启动沙箱吗？** 不一定。阅读说明由 Skill 路由处理；执行其中脚本才需要 Shell 环境。禁用沙箱时仍能读写工作文件和交付，但不提供对应执行能力。

**为什么使用租约而非直接缓存一个实例？** 需要表达 busy、失效、代际和过期时间，防止同会话多个执行段共用目录，或旧回收任务干扰新使用者。

**暂停恢复后能继续使用临时文件吗？** 未交付文件不保证保留。Checkpoint 不备份临时目录；恢复应加载已保存输入并重建中间文件。

**为什么复用后还上传 Skill？** 授权和包内容可能变化，且相关目录会重新初始化。复用节省实例创建，不代表跳过本轮能力部署。

**回收等于取消吗？** 不是。取消先结束执行控制，资源关闭发生在执行退出后；不能在仍执行时随意删除共用资源。
