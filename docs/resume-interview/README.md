## 如何使用

1. 先读写作思路和成稿，根据投递岗位选择条目；默认保留架构、任务、上下文与沙箱。
2. 每个模块先练「一分钟口述」，再对照「实现链路」解释技术细节。
3. 用追问题检查是否能解释为什么这样设计，而不只是背组件名称。
4. 沿代码入口读实现，结合自己实际完成的工作调整第一人称口述。
5. 用第 13 篇练习自我介绍和技术话题引导，再用第 11 篇做完整模拟，准备可以展示的功能过程。

## 材料口径

- 「当前实现」来自工作区代码与就近说明；没有在本轮启动服务、调用模型或验证部署状态。
- 从自建 LangGraph Agent 演进到 DeepAgents 的历史来自项目背景与本次讨论；没有重建历史分支或对比迁移前性能。
- 「一分钟口述」是讲解模板。个人分工、开发时间、真实故障和量化收益应按实际经历补充。
- 标为「进一步设计」或「建议采集」的内容是面试延伸，不算已经落地。
- 默认值只代表代码配置，可以被环境变量覆盖；不能当作容量或性能测试结果。
- 原有 platform 文档仍有参考价值；若类名、状态或生命周期与当前代码不同，本系列优先使用当前实现名称。

## 八个模块的职责边界

| 模块 | 核心职责 | 容易混淆的概念 |
| --- | --- | --- |
| Agent 装配 | 把在线配置变成授权后的运行图。 | 使用框架能力与自研调度器。 |
| 任务管理 | 控制一轮任务如何启动、等待、恢复和结束。 | 业务执行与后台执行片段。 |
| 流式事件 | 交付执行过程，恢复客户端展示。 | SSE 重连与图恢复。 |
| 上下文 | 组织当前模型输入，保留可复用信息。 | 摘要、Checkpoint、长期记忆、知识库。 |
| 工作区与沙箱 | 管理执行环境和文件生命周期。 | 临时副本、远程实例、持久化产物。 |
| 知识库 | 将文档转成可检索的资料。 | 关键词检索与 BM25、融合与 reranker。 |
| 工作流 | 将显式配置编译成受依赖约束的执行图。 | 条件汇聚与并行等待。 |
| 评估 | 对输出与候选产物作有依据的评分和验收。 | 报告完成、验收通过与模型训练。 |
