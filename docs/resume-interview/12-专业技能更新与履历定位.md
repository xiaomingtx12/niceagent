# 专业技能更新与履历定位

## 定位与依据

默认投递方向为 AI Agent 应用开发 / AI 后端开发。定位可表述为「具备 Java 后端与全栈实习基础，重点实践 Agent 平台工程的 2026 届本科毕业生」。教育经历使用实际学校、专业及 2026.07 毕业时间；具体招聘渠道的应届认定以岗位要求为准。

这份建议结合本地 NiceAgent 代码、Nice AI 学习沉淀仓库的结构及部分文章，以及用户提供的 StudyMQ 和实习描述。用户已明确智能客服助手没有真正实践，不列为已完成项目，也不作为 GraphRAG、Neo4j、Text2Cypher 或 FastAPI 实践依据。StudyMQ 后续已对照用户指定的 FastMQ 仓库做核心链路静态核对，见第 14 篇；实习代码未核对，不扩大成经过独立验证的性能或生产规模结论。

## 为什么旧版需要调整

旧版偏向框架名与模式名枚举，反复使用「熟练掌握」，对上下文、任务恢复、沙箱、评估等已经实现的工程能力体现不足。Prompt 部分将重点放在角色设定和 CoT，也不足以代表目前的系统实践。

更新后的技能应当回答「能实现什么、理解哪些关键机制、哪里有实践证明」。技能栏概括跨项目可迁移能力，项目经历再解释具体实现、问题和结果，不复制 NiceAgent 的全部功能条目。

Agent 部分围绕运行时、能力编排、上下文与执行治理组织，不再以 ReAct、Plan、Reflection 等模式名称作为能力主线。这里调整的是简历表达和项目定位，不将「ReAct 已经不再使用」作为未经验证的行业结论。

熟悉框架不等于实现框架本身；阅读源码不等于参与上游开发；使用 AI 编程工具不等于代码质量自动得到保证。避免没有对照实验的「显著降低资源消耗」「有效提升准确性」等收益结论。

## 推荐专业技能成稿

- **Agent 运行时与能力编排**：熟悉 LangChain、LangGraph、DeepAgents，能够围绕模型调用、工具执行、任务规划和状态管理构建运行链路，具备多 Agent 协作、能力动态装配及可恢复任务的工程实践。

- **上下文与记忆管理**：熟悉提示词装配与结构化输出约束，具备动静分离、上下文预算、摘要压缩和历史归档实践，能够结合 Checkpoint 与 Store 管理会话状态及跨会话文件记忆。

- **工具协议与执行环境**：熟悉工具调用、参数 Schema 与 MCP 服务接入，具备 API 工具集成和 Skills 能力装配经验，能够管理沙箱按需初始化、会话复用、资源回收及文件交付。

- **RAG 与知识库工程**：熟悉文档解析、清洗、分段、Embedding 和索引构建，具备 Weaviate/FAISS 向量检索实践，能够结合关键词召回构建混合检索，并处理知识库权限与向量模型一致性。

- **Agent 评估与验收**：理解 LLM-as-a-Judge 与 Rubric 评估方式，能够结合确定性规则开展历史回答评分、隔离执行和反馈修订，具备评估材料冻结、候选证据校验及异步评估任务实践。

- **后端与全栈开发**：使用 Python、Java 开发后端服务，熟悉 Flask、Spring Boot 与 MyBatis；具备 RESTful API、SSE 流式接口及异步任务开发经验，能够使用 JavaScript、Vue、UniApp 完成业务功能与接口联调。

- **数据库与消息中间件**：熟悉 MySQL、PostgreSQL 的数据建模、索引与事务，以及 Redis 缓存；具备 RabbitMQ 异步任务、幂等与重试实践，通过类 RocketMQ 学习项目理解注册发现、消息存储、顺序消费、时间轮及死信处理。

- **AI 辅助工程与源码分析**：使用 Codex、Claude Code 辅助开发，结合需求规格、任务拆分和代码审查组织迭代；持续围绕 LangChain 系列、Dify 等项目开展源码分析与工程复盘，并维护公开学习站点。

这份为完整候选版。投递时技能区通常控制在 6～8 条；必须能解释每个关键词的实际用法。MCP Server 开发、FastAPI 等能力若有客服项目以外的独立实践，可以再补入；当前不依据未实施方案默认声称具备。FAISS 使用深度和数据库调优经验按实际代码与复盘准备。

## 两处值得同步修正的技术措辞

### StudyMQ 的 MMap

「避免用户态内核态数据拷贝」过于绝对。MMap 将文件映射到进程地址空间，能够减少传统 read/write 路径中的部分复制与系统调用开销，仍涉及页缓存、缺页和实际读写过程。是否在某段链路形成零拷贝，需要结合具体数据路径说明。

可改成：「基于 MMap 实现 CommitLog 与 ConsumeQueue 分离存储，结合顺序追加、分段文件及索引定位组织消息持久化与读取。」只有实际测量后再加吞吐或资源收益。

### 未实践的客服与 GraphRAG

客服方案没有真正实践，应删除此前「图谱与向量协同检索实战」「Text2Cypher 查询实践」等表述。如果确实阅读过相关资料，可以在学习站展示笔记，明确属于学习分析。NiceAgent 现有知识库链路足以支撑 RAG 技能，无需借用未实现的图谱能力。

## 面试前技能证据清单

1. Agent：能画出模型、工具、子 Agent、Checkpoint、Store 与平台业务服务的边界。
2. Prompt：能给出动静分离、结构化输出失败处理和预算配置的实际代码入口。
3. MCP：能解释工具发现、Schema、调用、认证和传输方式，明确自己实现的是哪端、哪部分。
4. RAG：准备 NiceAgent 的文档分段与两路召回案例，说明关键词检索、向量检索和融合的边界。
5. 评估：解释裁判、规则、修订和证据哈希各自职责，区分任务完成与验收通过。
6. 后端：准备一个事务、幂等、异步任务或取消竞态案例，以及实习审批策略重构。
7. MQ：能讲 CommitLog/ConsumeQueue、消费确认与重试；顺序保证要说明并发、失败和多实例边界。
8. 源码分析：选两篇能现场沿真实函数讲解的文章，区分原文事实、个人判断和未验证推测。
