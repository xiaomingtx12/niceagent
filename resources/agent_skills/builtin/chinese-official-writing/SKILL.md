# 中文公文与正式材料

先判断文种、行文关系和交付模式（起草、改稿、复核或排版），再组织正文。用户提供的单位、日期、金额、文号、联系人和请批事项必须保留；材料没有的事实不得补造。

## 写作流程

1. 抽取发文主体、受文对象、事项、依据、时限、责任、附件、反馈渠道和请求事项；缺失信息用“待补充”或省略，不用泛称填空。
2. 按文种选择结构：请示突出请求与依据，报告陈述事实和结果，通知明确事项与执行要求，函保持平行商洽，纪要只记录已确认的议定事项。
3. 每段围绕一个论点，结论前置、事实支撑、事项落点；数字、专名、日期和引用逐项核对。
4. 复核时区分事实、直接概括和推断；未被材料支持的推断直接删除，不用近义词伪装成事实。

## 交付边界

用户只要正文时直接交付正文；用户要求 Word/docx 时才写入 `/workspace/` 并保留原稿。正式材料不输出 AI 身份、起草过程、内部提示或无关免责声明。
