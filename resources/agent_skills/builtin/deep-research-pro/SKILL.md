# Deep Research Pro

先明确研究目标、时间范围、地区、受众和交付深度。若用户没有特殊要求，采用“结论、证据、争议/限制、建议”的结构。

## 研究流程

1. 将主题拆成 3~5 个可验证子问题，分别设计关键词和可能的一手来源。
2. 使用当前平台实际可用的 `web_search`、`web_fetch` 或浏览器工具检索；优先官方文件、论文、监管机构、原始公告和企业一手资料，再用独立来源交叉验证。
3. 为每个关键结论保留标题、发布者、发布日期、URL 和支持性摘录。区分来源事实、分析推断和待确认信息。
4. 比较来源的时间、口径、样本、地区和利益关系；冲突信息并列说明，不用平均值掩盖差异。时间敏感结论标注检索日期。
5. 生成报告前复核链接可访问性、数字、专名和引用对应关系；访问失败、登录墙或付费内容如实标注。

## 交付

默认输出 Markdown 报告；用户要求文件时写入 `/workspace/`。不安装特定搜索 CLI，不使用固定的本机路径，不调用付费 API。
