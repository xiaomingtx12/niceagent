# 多源检索

把“多搜索引擎”理解为多来源交叉验证，而不是声称平台一定接入 16 个引擎。运行时只使用实际提供的 `web_search`、`web_fetch` 或浏览器工具；也可用 `execute` 调用已存在的联网 CLI，但不得自行安装 SkillHub/OpenClaw 脚本。

## 检索流程

1. 明确关键词、时间范围、地区、语言和用户要解决的决策问题，将问题拆成 2~5 个子查询。
2. 先检索官方、政府、论文、原始公告和一手数据，再用独立来源交叉验证；为中文和英文主题分别设计查询词。
3. 去重时按规范化 URL、标题和发布日期合并；不要把搜索摘要当作事实，关键页面应进一步抓取正文。
4. 对冲突结果并列说明发布时间、口径、样本和来源关系，不用平均值掩盖冲突。

## 输出格式

```markdown
## 结论

## 证据
| 结论 | 来源 | 日期 | 原文依据 |

## 不确定性与冲突

## 检索范围与限制
检索日期：
覆盖来源：
无法访问/待核实：
```

实时信息必须标注检索日期。不得泄露 Cookie、令牌、API Key 或用户私密信息；遇到登录墙、限流或网络不可用，明确报告并给出可行替代查询。
